AWS Console Deployment Steps

Step-by-step guide to deploy the Angular 19 + Spring Boot (Java 17) application to AWS ECS Fargate with a public Application Load Balancer (region: us-east-1).

Prerequisites Create ECR Push Image IAM Roles VPC & Subnets Security Groups Target Group ALB ECS Cluster Task Definition ECS Service Verify HTTPS

Prerequisites

  1. AWS console access with ECR, ECS, EC2, IAM, ELB, CloudWatch permissions (or admin for learning).
  2. Docker installed locally to build and push images.
  3. Project root contains the Dockerfile (multi-stage) and builds locally.

1 — Create ECR repository

  1. Console → Elastic Container Registry → Repositories → Create repository.
  2. Name: my-java-angular-app. Keep it private; enable image scanning if desired.
ECR stores images. ECS pulls images from ECR during task start.

2 — Push Docker image to ECR

Follow the repo's View push commands, or run these (replace <ACCOUNT>):

aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin <ACCOUNT>.dkr.ecr.us-east-1.amazonaws.com

docker build -t my-java-angular-app:latest .
docker tag my-java-angular-app:latest <ACCOUNT>.dkr.ecr.us-east-1.amazonaws.com/my-java-angular-app:latest
docker push <ACCOUNT>.dkr.ecr.us-east-1.amazonaws.com/my-java-angular-app:latest

3 — IAM roles (minimum)

  1. Create role ecsTaskExecutionRole: Trusted entity > AWS service > Elastic Container Service > Task. Attach AmazonECSTaskExecutionRolePolicy.
  2. Optionally create ecsTaskRole (for app permissions like S3 access). Keep least privilege.
Execution role allows ECR pulls and CloudWatch logging.

4 — VPC & Subnets

  • Use a multi-AZ VPC.
  • Public subnets (2+) for ALB. Private subnets (2+) for ECS tasks with a NAT gateway for outbound access.
  • For quick tests, the default VPC (public) is acceptable; don't use it for production.

5 — Security groups

ALB SG
  • Name: my-java-angular-alb-sg. Inbound: HTTP 80 from 0.0.0.0/0. Outbound: allow all.
Task SG
  • Name: my-java-angular-task-sg. Inbound: TCP 8080 from the ALB SG (use SG reference). Outbound: allow all.

6 — Target group (IP)

  1. EC2 → Target Groups → Create target group.
  2. Target type: IP. Protocol: HTTP. Port: 8080. Health check: / or /actuator/health.
  3. Name: my-java-angular-tg.
Fargate registers ENI IPs with the target group automatically.

7 — Application Load Balancer

  1. EC2 → Load Balancers → Create → Application Load Balancer.
  2. Name: my-java-angular-alb. Scheme: internet-facing. Subnets: select 2+ public subnets in different AZs.
  3. Use my-java-angular-alb-sg. Add listener HTTP :80 → forward to my-java-angular-tg.

8 — ECS Cluster (Fargate)

  1. ECS → Clusters → Create cluster → Networking only (Fargate). Name: my-java-angular-cluster.

9 — Task definition (Fargate)

  1. ECS → Task Definitions → Create new → FARGATE.
  2. Family: my-java-angular-task. Execution role: ecsTaskExecutionRole.
  3. CPU: 512 (0.5 vCPU). Memory: 1024 (1 GB).
  4. Container:
    • Name: my-java-angular-container
    • Image: <ACCOUNT>.dkr.ecr.us-east-1.amazonaws.com/my-java-angular-app:latest
    • Port mapping: container port 8080
    • Logs: awslogs → Log group: /ecs/my-java-angular, stream prefix ecs

10 — Create ECS service

  1. ECS → Clusters → my-java-angular-cluster → Services → Create.
  2. Launch type: FARGATE. Task definition: my-java-angular-task. Service name: my-java-angular-service.
  3. Desired count: 1. Networking: choose VPC and private subnets; attach my-java-angular-task-sg.
  4. Load balancing: select ALB, use container my-java-angular-container:8080, target group my-java-angular-tg.
For testing you can enable public IPs; for production prefer private subnets and NAT gateway.

11 — Verify

  1. Check ECS: Tasks → status RUNNING and logs show successful start.
  2. Target Groups → my-java-angular-tg → Targets show healthy IPs.
  3. Load Balancers → my-java-angular-alb → DNS name → open in browser.

12 — Add HTTPS (optional)

  1. ACM (us-east-1): Request public certificate and validate (DNS preferred).
  2. Load Balancer → Listeners → Add listener HTTPS :443 and attach ACM cert → forward to target group.
  3. Optionally redirect HTTP :80 → HTTPS.

Recommendations

  • Use immutable tags (git SHA) for images and enable ECR scanning.
  • Enable CloudWatch alarms for unhealthy targets and high error rates.
  • Use autoscaling for the ECS service and deploy across AZs.
  • Store CI/CD credentials securely and prefer assume-role from Jenkins.
