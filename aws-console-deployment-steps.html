AWS Console Deployment Steps

Concise step-by-step AWS Console walkthrough to deploy the Angular 19 + Spring Boot (Java 17) app to ECS Fargate with a public Application Load Balancer (region: us-east-1).

Jump to: Prerequisites Create ECR repo Push image to ECR Create IAM roles VPC & Subnets Security Groups CloudWatch Logs Target Group Create ALB ECS Cluster Task Definition ECS Service Verify Add HTTPS (optional)

Prerequisites

  1. AWS Console access with permissions: ECR, ECS, IAM, EC2 (VPC/SG), ELB, CloudWatch Logs, and optionally ACM/Route53.
  2. Docker installed locally (to build and push the image).
  3. Your repository with Dockerfile at project root (multi-stage as provided).

1. Create ECR repository

  1. Console → Services → Elastic Container Registry → Repositories → Create repository.
  2. Repository name: my-java-angular-app. Visibility: Private. Enable image scanning (recommended).
  3. Click Create repository.
ECR stores your Docker images so ECS can pull them at runtime.

2. Push your Docker image to ECR

  1. Open your ECR repo page and click View push commands. Follow the four steps shown. Typical commands:
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin <ACCOUNT>.dkr.ecr.us-east-1.amazonaws.com

docker build -t my-java-angular-app:latest .

docker tag my-java-angular-app:latest <ACCOUNT>.dkr.ecr.us-east-1.amazonaws.com/my-java-angular-app:latest

docker push <ACCOUNT>.dkr.ecr.us-east-1.amazonaws.com/my-java-angular-app:latest

Replace <ACCOUNT> with your AWS account ID.

3. Create IAM role: ecsTaskExecutionRole

  1. Console → Services → IAM → Roles → Create role.
  2. Trusted entity: AWS service → Elastic Container Service → Task.
  3. Attach managed policy: AmazonECSTaskExecutionRolePolicy.
  4. Name: ecsTaskExecutionRole. Create role.

This role lets Fargate pull images from ECR and write logs to CloudWatch.

Optional: create ecsTaskRole

  1. Create a second role (same trusted entity) and attach least-privilege policies your app needs (e.g., S3 read only) or leave empty if not needed.
  2. Name: ecsTaskRole.

4. Choose or create VPC and subnets

  1. Console → VPC → Your VPCs. Use an existing multi-AZ VPC for production.
  2. Requirements:
    • At least 2 public subnets (for the ALB).
    • At least 2 private subnets (for ECS tasks) with a NAT gateway for egress.
  3. For quick testing you can use the default VPC (has public subnets), but production should use private subnets for tasks.

5. Create Security Groups

ALB security group

  1. VPC → Security Groups → Create security group.
  2. Name: my-java-angular-alb-sg. Inbound: HTTP (80) from 0.0.0.0/0. Outbound: allow all.

Task security group

  1. Create my-java-angular-task-sg in same VPC.
  2. Inbound: allow port 8080 from ALB security group (reference the ALB SG, not 0.0.0.0/0).
  3. Outbound: allow all (or restrict as needed).
This ensures only ALB can reach your app containers.

6. Create CloudWatch log group

  1. CloudWatch → Logs → Create log group → Name: /ecs/my-java-angular.
  2. Used by the task definition awslogs driver for container logs.

7. Create Target Group (type: IP)

  1. EC2 → Target Groups → Create target group.
  2. Target type: IP. Protocol: HTTP. Port: 8080. VPC: your VPC.
  3. Health check: Path / or /actuator/health. Create the target group: my-java-angular-tg.
Fargate tasks register their ENI IPs into an IP target group automatically.

8. Create Application Load Balancer (ALB)

  1. EC2 → Load Balancers → Create Load Balancer → Application Load Balancer.
  2. Name: my-java-angular-alb. Scheme: internet-facing. Subnets: choose 2+ public subnets in different AZs.
  3. Security group: my-java-angular-alb-sg. Listener: HTTP :80 → Default forward to my-java-angular-tg.
  4. Create the ALB.

9. Create ECS Cluster (Fargate)

  1. ECS → Clusters → Create cluster → Networking only (Fargate).
  2. Cluster name: my-java-angular-cluster. Create.

10. Register Task Definition (Fargate)

  1. ECS → Task Definitions → Create new Task Definition → FARGATE.
  2. Task name/family: my-java-angular-task.
  3. Task execution role: ecsTaskExecutionRole. Task role: ecsTaskRole (or None).
  4. Task CPU: 512 (0.5 vCPU). Memory: 1024 (1 GB).
  5. Add container definition:
    • Name: my-java-angular-container
    • Image: <ACCOUNT>.dkr.ecr.us-east-1.amazonaws.com/my-java-angular-app:latest
    • Port mapping: container port 8080
    • Logging: awslogs — log group: /ecs/my-java-angular, stream prefix: ecs
  6. Create the task definition.

11. Create ECS Service and attach ALB

  1. ECS → Clusters → my-java-angular-cluster → Services → Create.
  2. Launch type: FARGATE. Task definition: my-java-angular-task. Service name: my-java-angular-service. Desired count: 1.
  3. Networking: select VPC; select private subnets (recommended). Choose my-java-angular-task-sg security group.
  4. Load balancing: Application Load Balancer → choose my-java-angular-alb → container: my-java-angular-container:8080 → target group: my-java-angular-tg.
  5. Create service. ECS will launch tasks and register them with the target group.
For quick tests you can use public subnets and assign Public IP = ENABLED; for production prefer private subnets and NAT gateway.

12. Verify deployment

  1. In ECS, ensure Task status becomes RUNNING and that containers start without errors.
  2. EC2 → Target Groups → my-java-angular-tg → Targets: ensure targets are healthy.
  3. EC2 → Load Balancers → my-java-angular-alb → Description → DNS name: open in browser to see the app.

13. Add HTTPS (optional, production)

  1. ACM (us-east-1): Request a public certificate for your domain and validate ownership (DNS recommended).
  2. EC2 → Load Balancers → Listeners → Add listener: HTTPS :443. Select ACM certificate. Default action: forward to my-java-angular-tg.
  3. Optionally remove HTTP :80 listener or create a redirect from HTTP to HTTPS.

Notes & Recommendations

  • Run tasks in private subnets for security; use a NAT gateway for outbound internet access where required.
  • Use immutable image tags (git SHA) and ECR image scanning on push.
  • Set up Auto Scaling on the ECS service for availability and cost efficiency.
  • Store Jenkins credentials securely (Jenkins credentials store or assume-role approach).
  • Use CloudWatch alarms (unhealthy targets, high error rate) and automated rollback strategies if needed.
